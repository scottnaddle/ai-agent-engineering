# Chapter 1. AI 패러다임의 변화

## 1. 왜 중요한가

AI 기술은 지난 수십 년간 규칙 기반 시스템에서 딥러닝을 거쳐 대형 언어 모델(LLM)과 에이전트 시스템으로 발전해 왔다. 이 변화는 단순히 모델의 성능 향상에 그치는 것이 아니라, AI 활용 방식을 근본적으로 변화시키는 중요한 전환점이다. 과거에는 특정 문제에 특화된 AI 시스템이 주를 이루었다면, 이제는 목적 지향적이고 자율적 판단을 수행하는 'AI 에이전트'가 다양한 도구와 상호작용하며 복잡한 목표를 달성한다. 이러한 패러다임 변화는 AI 엔지니어, 백엔드/플랫폼 개발자, 그리고 LLM 기반 제품을 설계하는 PM/테크 리드 모두에게 새로운 설계 및 구현 방식, 인프라 구성, 시스템 통합의 필요성을 제기한다. 현대 AI 시스템을 이해하고 설계하는 데 있어, AI 에이전트 패러다임의 본질과 실무적 의미를 명확히 파악하는 것이 필수적이다.

## 2. 핵심 개념

### 2.1 AI 기술 발전 단계

AI 발전사는 세 단계로 정리할 수 있다.

| 발전 단계             | 주 개념             | 동작 방식           | 한계점                          |
|:------------------|:-----------------|:-------------------|:------------------------------|
| 규칙 기반 (Rule-based) | if-then 규칙       | 룰 집합에 따라 결정    | 범용성, 적응력 부족                  |
| 머신러닝 (ML)         | 데이터 기반 학습     | 특징 추출 후 학습     | 대량 데이터/특정 태스크 의존             |
| 딥러닝 (DL)           | 인공신경망          | 표현학습 자동화      | 블랙박스화, 설명력 부족                  |
| 대형 언어 모델(LLM)   | 대규모 사전학습     | 문맥 기반 추론       | 지식 업데이트 어려움, 도구 활용 한계         |
| 에이전트 시스템       | 추론, 도구, 메모리  | 목적 지향적 행동     | 신뢰성·조정 어려움, 기술 초기 단계 고려 필요 |

#### AI 발전 단계 다이어그램(Mermaid)

```mermaid
graph TD
    A[규칙 기반 <br> (Rule-based)] --> B[머신러닝 <br> (Machine Learning)]
    B --> C[딥러닝 <br> (Deep Learning)]
    C --> D[대형 언어 모델 <br> (LLM)]
    D --> E[에이전트 <br> 시스템]
```

### 2.2 LLM과 에이전트 패러다임

-   **LLM의 등장:** 방대한 텍스트 데이터로 사전학습된 LLM은 자연어, 코드, 다양한 도메인의 문제에 대해 문맥 기반 추론을 수행할 수 있게 되었다.
-   **에이전트 개념:** LLM에 도구(Tool), 메모리(Memory)와 같은 기능을 결합하여 단순 질의응답을 넘어, 반복적 계획·실행(Plan-Execute) 및 외부 시스템 사용이 가능한 'AI 에이전트'로 확장하는 개념이다.
-   **기존 AI와 차이:** 규칙 기반 또는 머신러닝 시스템이 정적 입력-출력에 제한적이었다면, 에이전트는 동적 계획, 도구 호출, 환경과의 상호작용을 수행하며 복합적인 목표를 주도적으로 달성할 수 있다.

## 3. 동작 구조

### 3.1 LLM 기반 에이전트 시스템의 기본 아키텍처

1.  **목표 입력:** 사용자가 자연어 등으로 목표를 입력한다.
2.  **계획 수립:** LLM이 목표 달성을 위한 단계별 계획(Plan)을 수립한다.
3.  **실행 및 도구 호출:** 필요한 API 호출, 코드 실행, 데이터 검색 등 도구를 활용하여 단계별 실행(Execute)을 수행한다.
4.  **상태 및 메모리 관리:** 과정에서 생성된 정보와 대화/업무 상태를 메모리에 저장 및 관리한다.
5.  **반복적 추론 및 조정:** 결과를 평가하고, 필요시 재계획하거나 수정한다(Loop).

```
목표 입력 → 계획(Plan) → 실행(도구 호출, 코드 실행 등) → 상태 및 메모리 기록 → 반복/조정 → 완료
```

### 3.2 주요 구성 요소 정의

-   **LLM (Large Language Model):** 자연어 의미 파악 및 추론을 수행한다.
-   **도구 (Tool):** 외부 시스템, API 호출, 코드 실행 환경 등과의 상호작용을 가능하게 한다.
-   **메모리 (Memory):** 현재 상태, 진행 내역, 과거 경험을 저장하고 관리한다.
-   **컨트롤러:** 에이전트의 전체 동작 흐름을 관리한다 (필요에 따라 Agent-Controller 형태로 구현될 수 있음).

## 4. 대표 패턴

### 4.1 기존 AI 애플리케이션과 에이전트 기반의 구조 비교

| 구분                  | 기존 AI 애플리케이션             | 에이전트 기반 애플리케이션          |
|---------------------|--------------------------------|--------------------------------|
| 접근 방식             | 단일 입력 → 단일 예측(결과)      | 목표 기반 계획·실행 반복           |
| 동작 방식             | 패턴/규칙/모델로 직접 예측         | 추론-도구 호출-메모리 반복적 동작    |
| 확장성               | 명확한 도메인, 범위 한정           | 도구·외부 환경 통합, 범용적 확장성     |
| 엔지니어링 방식         | ML/DL 모델 개발 및 배포에 집중     | 에이전트의 워크플로 설계, 도구 연동, 상태 관리에 집중 |

### 4.2 Agentic RAG 구조의 부상

기존 Retrieval-Augmented Generation(RAG)이 '검색→생성'의 단일 흐름이었다면, Agentic RAG는 계획-실행(Plan-Execute), 복수 검색·도구 호출, 결과 평가·재시도 등 다단계 흐름을 지원한다.

## 5. 실무 적용 포인트

-   **설계 관점 변화:** 모델 성능 향상만이 아닌, 에이전트의 목적 지향적 행동, 도구/외부 환경 연계, 워크플로 설계 역량의 중요성이 커졌다.
-   **통합 인프라 필요:** LLM, 도구, 메모리, 컨트롤러 간의 연동 설계와, 대화 상태·사용자 경험·결과 추적에 대한 시스템적 고려가 필요하다.
-   **확장 및 유지보수:** 다양한 API 및 도구 업데이트, 메모리 동기화/최적화, 프롬프트 전략 관리 등 운용 측면에서의 과제가 존재한다.
-   **엔지니어 역할 변화:** AI 모델 개발뿐 아니라, 시스템 통합, 서비스 확장성, 신뢰성 설계까지 역할이 확대된다.

## 6. 예제 코드

아래는 LLM에 '계획-실행' 사고 과정을 요구하는 기본 프롬프트와 이를 시뮬레이션하는 예시이다.

```python
import openai  # 또는 openai-compatible 라이브러리 사용

def agentic_plan_and_execute(prompt):
    system_instruction = ("당신은 목표를 달성하기 위해 계획을 세우고 각 단계를 차례대로 설명할 수 있는 에이전트입니다. "
                          "아래의 목표를 꼼꼼히 읽고, 계획을 세운 뒤 각 단계별로 실행 코드를 제안하세요.")
    user_prompt = f"목표: {prompt}\n계획을 세우고 각 단계를 실행하는 코드를 알려주세요."
    response = openai.ChatCompletion.create(
        model="gpt-3.5-turbo",  # 또는 호환 LLM 모델명
        messages=[
            {"role": "system", "content": system_instruction},
            {"role": "user", "content": user_prompt},
        ],
        temperature=0
    )
    return response["choices"][0]["message"]["content"]

# 사용법 예시:
goal = "CSV 파일에서 특정 컬럼의 평균값을 계산하세요."
print(agentic_plan_and_execute(goal))
```

#### 프롬프트 결과 예시

```
1. CSV 파일을 읽어들입니다.
2. 특정 컬럼(예: 'score')을 선택합니다.
3. 평균값을 계산합니다.

예시 코드:
import pandas as pd
df = pd.read_csv('data.csv')
mean_score = df['score'].mean()
print(mean_score)
```

이 예제는 LLM이 '계획-실행' 흐름을 프롬프트 수준에서 시뮬레이트하는 과정을 보여준다. 실제 구현에서는 이 계획을 바탕으로 코드 실행 환경이나 외부 도구 호출과 연계하게 된다.

## 7. 주의할 점

-   **과도한 기대 경계:** 현시점의 에이전트 시스템은 논리적 추론, 도구 활용, 결과 평가에서 오류나 신뢰도 문제가 여전히 존재한다.
-   **기술 초기 단계:** 에이전트 프레임워크와 프로토콜이 빠르게 발전하고 있으나, 표준화되거나 검증된 방법론은 아직 부족하다.
-   **성능과 제어의 균형:** LLM의 생성 능력과 시스템 통제(코드 실행, 도구 호출)의 안전성 사이에서 적정한 균형점을 찾아야 한다.
-   **벤더/기술 종속성 주의:** 특정 오픈소스 또는 벤더의 기능에 과도하게 의존하는 대신, 일반적인 AI 에이전트의 구조와 원리를 우선 파악해야 한다.

## 8. 요약

AI의 패러다임은 규칙 기반에서 딥러닝, LLM을 거쳐 에이전트 시스템으로 발전해 왔다. LLM과 도구·메모리를 결합한 에이전트는 목표 달성을 향한 계획-실행-조정 주기를 반복하며, 기존의 단일 응답형 AI를 넘어 복잡한 작업을 자율적으로 처리할 수 있게 한다. 이러한 변화는 개발·운영 방식, 설계 관점, 엔지니어의 역할까지 변화시키며 새로운 실무적 과제를 제시한다. 현재는 표준화 및 신뢰성 측면에서 한계가 존재하나, 이러한 패러다임의 이해와 대응이 미래 AI 시스템 구축에 있어 중요한 경쟁력이 될 것이다.
